# Slim Installer & First-Run Setup (Phase 5a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the ~4.9 GB PyInstaller bundle with an Inno Setup installer of about 200 MB. It installs per-user by default, ships the official python.org 3.13 runtime, and runs a first-run setup that installs locked ML libraries (GPU or CPU) into `%LOCALAPPDATA%\CampaignScribe\env`.

**Architecture:**
- A new `app/core/paths.py` gives every bundled-file lookup an "installed" mode.
- `locks/` holds exact, fully transitive library sets, generated by `scripts/make_locks.py`.
- `bootstrap/` (standard library plus Tk only) decides whether to launch, set up or switch. It runs pip with progress and launches the app inside the environment.
- `installer/CampaignScribe.iss` plus `build_installer.bat` package everything. The build fetches the pinned python.org zip.

**Tech Stack:** Python 3.13 (official python.org runtime), Tkinter, pip/venv, Inno Setup 6, pytest.

**Spec:** `docs/superpowers/specs/2026-10-05-slim-installer-design.md`

## Review Focus

1. **Deep paths:** a user profile with a long name pushes torch DLL paths past 260 characters. Expected: the setup refuses with a clear message if `len(env path) > 80`, rather than breaking at import. Task 3 pins this.
2. **An interrupted first run** (closing the window, a network drop, a crash): the next launch must not treat a partial environment as complete. Only an atomic `cs-setup.json` written after verification counts. Tasks 3 and 4 pin this.
3. **All-users installs, second user:** the read-only `{app}` is shared, but each user gets their own environment. Nothing ever tries to write under `{app}` at runtime. Task 1 adds a test that `paths` never returns a writable location under `app_home()`.
4. **The GPU profile on a machine where CUDA isn't usable:** setup completes with the CUDA warning, and the app runs on the CPU through `check_gpu()`. Task 3 pins this.
5. **Upgrade with a running app:** the installer's Restart Manager closes it. The lock-hash mismatch after an upgrade triggers a re-setup of the same profile, not a profile prompt. Tasks 3 and 6 pin this.

### Task 2: Locked library sets (`locks/`, `scripts/make_locks.py`)

**Files:**
- Create: `scripts/make_locks.py`, `tests/unit/test_make_locks.py`, `locks/gpu.txt`, `locks/cpu.txt`, `locks/README.md`

**Interfaces:**
- `make_locks.render(freeze_lines: list[str], *, profile: "gpu"|"cpu", python_version: str, pip_version: str, dev_only: set[str], date: str) -> str`
- `make_locks.lock_sha256(path) -> str`, which normalises CRLF to LF.
- CLI: `python scripts/make_locks.py --profile gpu|cpu --venv <path> --out locks/<profile>.txt`. It reads the freeze through `<venv>\Scripts\python -m pip list --format=freeze --exclude-editable`.

**Rendered lock format:**
- First, header comments: `# CampaignScribe <profile> lock — Python <ver> — generated <date>` and `# pip==<ver>`.
- Then `--extra-index-url https://download.pytorch.org/whl/cu128` (or `/whl/cpu`).
- Then the sorted `name==version` lines, with names lower-cased and `_`/`.` normalised to `-`.
- Excluded:
  - `pip` and `setuptools`, unless the app imports setuptools; check `pkg_resources` use and keep it if needed;
  - `wheel`;
  - `torchvision`;
  - any name in `dev_only`, which is the set of `requirements-dev.txt` top-level names **minus** names that also appear in `requirements.txt`.
- **Validation:**
  - For the gpu profile, `render` raises if torch or torchaudio isn't `+cu128`; for cpu, if it isn't `+cpu`.
  - It raises if `whisperx`, `pyannote-audio`, `torch` or `faster-whisper` is missing.

- [ ] **Step 1: Tests for `render`:** filtering, normalisation, sorting, header and index lines, validation errors, and `lock_sha256` CRLF equality. The tests are pure and use string fixtures.
- [ ] **Step 2: Implement.**
- [ ] **Step 3: Generate the real locks from clean, app-only environments.** Use short paths, to avoid the 260-character trap:
  - **GPU environment:** at `C:\cs-lock\gpu`, build with the official 3.13 (`py -3.13 -m venv`). Then:
    - run `setup_venv.bat`'s two-step app install with `requirements.txt`'s pins, **without** `requirements-dev.txt`;
    - uninstall torchvision;
    - run `python -c "import torch, whisperx, pyannote.audio, faster_whisper, app"` from the repo root;
    - then `make_locks --profile gpu`.
  - **CPU environment:** at `C:\cs-lock\cpu`, the same steps, with torch and torchaudio `==2.11.0+cpu` from the cpu index.
  - **Proof the GPU lock installs:** in a third clean environment, run `pip install --no-deps -r locks/gpu.txt`, then the full **test suite** using that environment plus `pip install -r requirements-dev.txt`, and a real GPU transcription of `scratchpad\spike7\clip16k.wav`. The baseline is 238 segments and 6 speakers.
  - **Afterwards,** remove `C:\cs-lock` and report the sizes.
- [ ] **Step 4:** `locks/README.md` explains when and how to regenerate the locks.
- [ ] **Step 5:** run the gate, then commit `build: exact GPU and CPU library locks for first-run setup`.

### Task 3: Bootstrap core (standard library, Tk-free) — `bootstrap/core.py`

**Files:**
- Create: `bootstrap/__init__.py`, `bootstrap/core.py`, `tests/unit/test_bootstrap_core.py`, `tests/unit/test_bootstrap_stdlib_only.py`

**Interfaces** (all pure or injectable):
- `env_dir() -> Path`, which is `%LOCALAPPDATA%\CampaignScribe\env`.
- `state_path()` and `setup_log_path()`.
- `read_state() -> dict | None`. A corrupt or missing file returns None.
- `write_state(profile, lock_sha, python_ver)`: atomic, temp file then `os.replace`.
- `lock_path(app_home, profile)` and `lock_sha256(path)`, the same normalisation as Task 2. Import from `scripts`? No: copy the 5-line function and add a test asserting both give identical results on a fixture.
- `decide(state, app_home, env_python_exists: bool, requested_switch: str | None) -> ("launch", profile) | ("setup", default_profile_or_None) | ("resetup", profile)`.
  - `resetup` means the same profile with a different lock hash; this is the upgrade path in Review Focus 5.
  - A requested switch gives `("setup", that_profile)`.
- `detect_nvidia(run=subprocess.run) -> {"found": bool, "name": str, "driver": str}`. It parses `nvidia-smi --query-gpu=name,driver_version --format=csv,noheader` and looks on PATH, then in `%SystemRoot%\System32`, with a 10 s timeout and `CREATE_NO_WINDOW`.
- `required_bytes(profile)`: GPU is 6 GB plus 2 GB headroom; CPU is 1.6 GB plus 2 GB.
- `disk_ok(path, profile) -> (ok, free_bytes)`.
- `path_ok(env_dir) -> bool`, which checks `len(str(env_dir)) <= 80` (Review Focus 1).
- `pip_command(env_python, lock_file) -> list[str]`, with exactly the flags from the spec plus `--retries 5 --timeout 60`.
- `ProgressCounter(total_lines)` with `.feed(line) -> (done, total, current_name | None)`. It counts lines starting with `Collecting`, `Downloading`, `Using cached` and `Installing collected packages`, and also handles pip's `Successfully installed …`.
- `verify_command(env_python) -> list[str]` and `parse_verify(stdout) -> (torch_version, cuda_ok)`.
- `launch_command(env_pythonw, app_home) -> (list[str], env)`, setting `CAMPAIGNSCRIBE_HOME`.

- [ ] **Step 1: Tests for every function,** Linux-safe:
  - `env_dir` uses a monkeypatched `LOCALAPPDATA` (tmp);
  - fake `run` results for nvidia-smi: found, not found, timeout, odd output;
  - a monkeypatched `shutil.disk_usage`;
  - all `decide` branches, including a corrupt state and a missing env python;
  - the progress counter against a captured real pip log excerpt (write a small fixture from Task 2's install log);
  - `parse_verify` for both True and False.

  `test_bootstrap_stdlib_only.py` parses every `bootstrap/*.py` with `ast` and asserts each import is in `sys.stdlib_module_names`, or is `bootstrap` itself.

### Task 4: Setup window and launcher — `bootstrap/setup_window.py`, `bootstrap/launcher.py`

**Files:**
- Create: `bootstrap/setup_window.py`, `bootstrap/launcher.py`, `tests/gui/test_bootstrap_setup_window.py`, `tests/unit/test_launcher_main.py`

**Interfaces:**
- `SetupWindow(root, *, app_home, profile_default, nvidia, installer: Callable, on_done: Callable, spawn=threading-default)`.
- `installer(profile, log_cb, progress_cb) -> InstallResult(ok, cuda_ok, message)` is an injected function: the real one runs venv, pip upgrade, pip install and verify using Task 3's commands; tests pass fakes.
- `launcher.main(argv) -> int`: parses `--switch gpu|cpu`, resolves `app_home` from `__file__`'s parent's parent, calls `decide`, and then:
  - **launch:** Popen the app with `launch_command`, then exit 0;
  - **setup or resetup:** show the window, with resetup skipping the profile choice and starting the install immediately, then launch on success.

**Window behaviour** (from the spec, §2):
- the radio choice with the detected GPU name, the captions and the no-GPU warning;
- disk and path checks that disable **Install**, with the exact messages;
- during install: a progress bar, a current-package status line and a collapsible log, all updated through `after()` from the worker;
- failure: the last 30 log lines plus **Retry** and **Quit**;
- the close button while installing asks to confirm. On confirm it terminates pip through the installer's cancel hook, deletes the partial environment, and quits;
- the CUDA warning when `cuda_ok` is False, with a **Continue** that launches anyway.

`write_state` is called **only** after a successful verify (Review Focus 2). The real installer's `venv` step deletes a partial or old `env_dir` first, but only after confirming `cs-setup.json` is absent or that this is a switch.

- [ ] **Step 1: GUI tests with fake installers.**
  - **Success:** the state is written and `on_done` is called.
  - **Failure, then Retry, then success:** there are two installer calls, and the state is written once.
  - **Close while installing:** the confirm is patched; the cancel hook is called, no state is written, and the window is destroyed.
  - **GPU preselection** when `nvidia.found`, CPU otherwise.
  - The exact strings.
  - The low-disk and long-path blocks.
  - **Resetup mode:** no radio, and the install starts at once.

  `test_launcher_main.py` (unit) patches `decide`, `Popen` and `SetupWindow` and checks each branch returns the right code. **Patch every dialog.**
- [ ] **Step 2: Implement.** The real installer function lives in `bootstrap/install.py`, which is also standard library only. Unit-test it with a fake `run` that records the command sequence: venv, then pip upgrade, then install, then verify. It must stop at the first failure and produce `InstallResult`.

## Manual acceptance (controller, on this PC)

1. **Install for me only:** run `dist-installer\CampaignScribe-Setup-<v>.exe`. There's no admin prompt. The license and privacy pages show, and the Start-menu and Installed-apps entries appear.
2. **First launch:**
   - the Setup window shows the RTX 4080 with GPU preselected;
   - Install runs with progress;
   - the app opens, and its taskbar icon is CampaignScribe;
   - Transcribe of a test clip on the GPU matches the baseline.
3. **Relaunch:** goes straight to the app.
4. **Settings, then Switch to CPU:** the CPU environment installs and the app runs on the CPU. Switch back to GPU.
5. **Re-run the installer over the top, simulating an upgrade:** it closes the running app, and no profile prompt appears unless the locks changed.
6. **Uninstall:** the engine prompt appears; on Yes, `env` is removed; `%APPDATA%\CampaignScribe` is kept.
7. **Network failure:** disconnect mid-install, then use Retry.
